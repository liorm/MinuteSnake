# Phase 2.1: Multiplayer Game Logic

## Objective
Adapt the existing shared GameLogic for server-side execution and implement game state broadcasting to all connected players.

## Tasks

### Server-Side Game Logic
1. **Adapt GameLogic for Server**
   - Move GameLogic execution to Durable Object
   - Implement deterministic game state updates
   - Handle multiple player inputs simultaneously
   - Maintain game state consistency

2. **Input Validation & Processing**
   - Validate all incoming player inputs
   - Implement input sanitization
   - Handle input timing and ordering
   - Prevent cheating and invalid moves

3. **State Broadcasting**
   - Broadcast game state updates to all players
   - Implement delta compression for efficiency
   - Handle player-specific state information
   - Manage update frequency and timing

4. **Game Synchronization**
   - Ensure all clients receive consistent state
   - Handle network lag and out-of-order messages
   - Implement server-authoritative game model
   - Manage game timing and tick rates

## Technical Specifications

### Server-Side Game State Management
```typescript
class MultiplayerGameLogic {
  private gameState: IGameState
  private players: Map<string, PlayerState>
  private gameStage: IGameStage
  
  // Game loop management
  startGame(): void
  updateGame(deltaTime: number): void
  processPlayerInput(playerId: string, input: GameInput): boolean
  
  // State broadcasting
  broadcastGameState(): void
  getPlayerSpecificState(playerId: string): PlayerGameState
}

interface PlayerState {
  playerId: string
  snakeIndex: number
  isActive: boolean
  lastInputTime: number
}

interface PlayerGameState extends IGameState {
  playerId: string
  playerSnakeIndex: number
}
```

### Game Input Processing
```typescript
interface NetworkGameInput extends GameInput {
  playerId: string
  clientTimestamp: number
  serverTimestamp: number
}

interface GameInputResult {
  accepted: boolean
  reason?: string
  newState?: IGameState
}
```

### State Broadcasting Protocol
```typescript
interface GameStateUpdate {
  type: 'gameState'
  state: IGameState
  timestamp: number
  tickNumber: number
}

interface GameDelta {
  type: 'gameDelta'
  changes: StateChange[]
  timestamp: number
  tickNumber: number
}
```

## Integration with Existing Code
- Utilize existing `@minute-snake/shared` GameLogic

## Game Flow
1. Server maintains authoritative game state
2. Players send input commands to server
3. Server validates and processes inputs
4. Server updates game state using GameLogic
5. Server broadcasts state updates to all players
6. Clients render received state

- State broadcasting mechanism
- Integration with existing GameLogic

## Success Criteria
- Game state remains consistent across all clients
- All player inputs are validated server-side
- Game runs smoothly with multiple simultaneous players
- State updates are efficiently broadcast
- Existing single-player functionality remains intact
- Game logic handles edge cases (disconnections, invalid inputs)
