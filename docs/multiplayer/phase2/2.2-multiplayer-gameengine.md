# Phase 2.2: Multiplayer GameEngine

## Objective
Create a new `MultiplayerHandler` that extends `GameHandlerBase` to handle networked gameplay with client-side prediction and server reconciliation.

## Tasks

### MultiplayerHandler Implementation
1. **Create MultiplayerHandler Class**
   - Extend `GameHandlerBase` interface
   - Implement client-side prediction
   - Handle server state reconciliation
   - Manage network input and local input

2. **Client-Side Prediction**
   - Predict game state changes locally
   - Apply inputs immediately for responsiveness
   - Store prediction history for reconciliation
   - Handle prediction corrections from server

3. **Server Reconciliation**
   - Compare server state with predicted state
   - Correct client state when discrepancies found
   - Replay inputs after correction point
   - Smooth visual transitions during corrections

4. **Network Input Handling**
   - Send local player inputs to server
   - Receive and process server state updates
   - Handle input acknowledgments
   - Manage input buffering and queuing

## Technical Specifications

### MultiplayerHandler Class
```typescript
class MultiplayerHandler extends GameHandlerBase {
  private webSocketClient: GameWebSocketClient
  private predictedState: IGameState
  private serverState: IGameState
  private predictionHistory: PredictionFrame[]
  private pendingInputs: NetworkGameInput[]
  
  // GameHandlerBase implementation
  get gameStage(): IGameStage
  get state(): IGameState
  get savedInputs(): IGameEventInput[]
  get isDone(): boolean
  
  advanceTime(duration: number): void
  performInput(input: GameInput): void
  
  // Multiplayer-specific methods
  private reconcileWithServer(serverState: IGameState): void
  private applyPrediction(input: GameInput): void
  private replayPredictions(): void
}

interface PredictionFrame {
  tickNumber: number
  input: GameInput
  stateAfterInput: IGameState
  timestamp: number
}
```

### Input Flow Architecture
```typescript
// Local input processing
1. Player presses key
2. Input immediately applied to predicted state
3. Input sent to server via WebSocket
4. Predicted state rendered to player

// Server reconciliation
1. Server state update received
2. Compare with predicted state at same tick
3. If different, correct client state
4. Replay all inputs after correction point
5. Update display smoothly
```

### State Management
```typescript
interface ClientGameState {
  // Server-authoritative state
  serverState: IGameState
  serverTick: number
  
  // Client prediction state
  predictedState: IGameState
  predictedTick: number
  
  // Reconciliation data
  lastReconciliationTick: number
  pendingCorrection: boolean
}
```
