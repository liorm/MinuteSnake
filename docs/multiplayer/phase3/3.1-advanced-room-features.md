# Phase 3.1: Advanced Room Features

## Objective
Implement advanced room management features including capacity limits, dynamic player join/leave during gameplay, and spectator mode.

## Tasks

### Room Capacity Management
1. **Player Limits**
   - Configurable maximum players per room
   - Queue system for full rooms
   - Room status tracking (open, full, playing, finished)
   - Automatic room scaling considerations

2. **Dynamic Join/Leave**
   - Allow players to join games in progress
   - Handle player disconnections during gameplay
   - Redistribute game elements when players leave
   - Maintain game balance with changing player count

3. **Spectator Mode**
   - Convert disconnected players to spectators
   - Allow new connections as spectators
   - Spectator-specific UI and controls
   - Limit spectator count to prevent resource issues

4. **Room State Persistence**
   - Save room state during player transitions
   - Handle room recovery after all players disconnect
   - Implement room timeout and cleanup policies
   - Maintain game continuity across connections

## Technical Specifications

### Enhanced Room Management
```typescript
interface RoomConfig {
  maxPlayers: number
  maxSpectators: number
  allowJoinInProgress: boolean
  allowSpectators: boolean
  roomTimeout: number
}

interface RoomState {
  roomId: string
  status: RoomStatus
  players: Map<string, PlayerInfo>
  spectators: Map<string, SpectatorInfo>
  gameState?: IGameState
  config: RoomConfig
}

enum RoomStatus {
  Waiting = 'waiting',
  Starting = 'starting',
  Playing = 'playing',
  Paused = 'paused',
  Finished = 'finished',
  Closed = 'closed'
}

interface PlayerInfo {
  playerId: string
  playerName: string
  snakeIndex?: number
  connectionStatus: ConnectionStatus
  joinTime: number
  lastActivity: number
}

interface SpectatorInfo {
  spectatorId: string
  spectatorName: string
  joinTime: number
  lastActivity: number
}
```

### Dynamic Player Management
```typescript
class AdvancedRoomManager {
  // Player management
  async addPlayer(playerInfo: PlayerInfo): Promise<JoinResult>
  async removePlayer(playerId: string, reason: string): Promise<void>
  async convertToSpectator(playerId: string): Promise<void>
  
  // Game state management
  async pauseGame(reason: string): Promise<void>
  async resumeGame(): Promise<void>
  async redistributeSnakes(): Promise<void>
  
  // Room lifecycle
  async checkRoomViability(): Promise<boolean>
  async cleanupEmptyRoom(): Promise<void>
}

interface JoinResult {
  success: boolean
  role: 'player' | 'spectator' | 'queued'
  snakeIndex?: number
  reason?: string
}
```

## Game Integration
1. **Pause/Resume Logic**
   - Automatic pause when critical players disconnect
   - Vote system for pause/resume decisions
   - Timeout handling for extended pauses

2. **Snake Redistribution**
   - Remove snakes of disconnected players
   - Reassign snake indices for remaining players
   - Handle power-ups and score redistribution

3. **Spectator Rendering**
   - Separate rendering pipeline for spectators
   - Enhanced view options (mini-map, player stats)
   - Spectator-specific UI elements

## Player Experience
1. **Smooth Transitions**
   - Seamless conversion between player and spectator
   - Clear notifications for room state changes
   - Graceful handling of disconnections

2. **Fair Gameplay**
   - Prevent mid-game joining advantages
   - Balance considerations for dynamic player count
   - Anti-griefing measures for frequent join/leave

## Deliverables
- Enhanced room management system
- Dynamic player join/leave functionality
- Spectator mode implementation
- Room state persistence
- Player experience optimizations

## Success Criteria
- Rooms handle player capacity limits correctly
- Players can join games in progress when allowed
- Spectator mode provides good viewing experience
- Disconnected players don't break ongoing games
- Room state persists through player transitions
- Performance remains stable with spectators
- Game balance maintained during player changes
