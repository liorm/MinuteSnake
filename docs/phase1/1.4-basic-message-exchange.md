# Phase 1.4: Basic Message Exchange

## Objective
Implement core message types and establish bidirectional communication between frontend and backend.

## Tasks

### Message Type Implementation
1. **Core Message Types**
   - Join room messages
   - Leave room messages
   - Ping/Pong for connection health
   - Simple chat messages for testing

2. **Message Protocol Design**
   - Standardized message format

3. **Communication Testing**

4. **Room Discovery**
   - Simple room finding logic

   - Room ID generation
   - Basic room metadata

## Technical Specifications

### Message Protocol
```typescript
interface BaseMessage {
  id: string
  type: MessageType
  timestamp: number
  playerId?: string
}

interface JoinRoomMessage extends BaseMessage {
  type: 'join'
  payload: {
    roomId?: string
    playerName: string
  }
}

interface LeaveRoomMessage extends BaseMessage {
  type: 'leave'
  payload: {
    reason?: string
  }
}

interface PingMessage extends BaseMessage {
  type: 'ping'
}

interface PongMessage extends BaseMessage {
  type: 'pong'
}

interface ChatMessage extends BaseMessage {
  type: 'chat'
  payload: {
    message: string
  }
}

interface ErrorMessage extends BaseMessage {
  type: 'error'
  payload: {
    code: string
    message: string
  }
}
```

### Room Discovery Logic
```typescript
interface RoomInfo {
  roomId: string
  playerCount: number
  maxPlayers: number
  status: 'waiting' | 'playing' | 'finished'
}
```

## Implementation Flow
1. Client sends join request (with or without specific room ID)
2. Server finds available room or creates new one
3. Server responds with room assignment
4. Client confirms join and receives room member list
5. Basic chat messages for testing communication

## Deliverables

- Message validation functions
- Room discovery implementation

## Success Criteria
